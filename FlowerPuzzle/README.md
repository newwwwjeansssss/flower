# 花田拼图关卡编辑器

2026-10-27：原「花田试玩 · 前25关」已扩展为 **花田试玩 · 1–25 / 31–42关**，新增12关重叠布局，26—30留空。刷新后选择新列表；详见 [31—42关设计与验证](docs/overlap-trial-design.md)。下文前25关说明保留历史口径。

2026-10-27 第六版：31—42关已按局部落笔线索重新排布。每个数字格由凸角、边沿或提示栅栏引入；31—36起手唯一，37—42保留1—3种局部选择。详见上方设计与验证文档及 [可视总览](docs/overlap-silhouettes.html)。

Windows 运行 `start.exe`，macOS 双击 `Start.command` 打开可读写编辑器。普通浏览器打开 `index.html` 时为只读演示。

2026-10-27 第三版：31—42关已重做为紧凑、多样化重叠布局（17—25有效格，无封闭内部空洞），加入端点、同向接续、转角共格、共边和双点连接。详见上述设计说明。

- 玩家绘制：按住拖动时可以反复经过本次已经画过的格子，再从旧格子继续画分支；松开后同一格只计算一次。经过相邻格、围栏和其他花块的限制仍然生效。
- 画布编辑：进入编辑后，可还原或删除格子，并在现有格子上放置预置花盆、固定花朵。
- 预置选择：左键拖选同一目标花块中的格子（可以选中整个形状），再在选区内右键设置或取消预置花盆；固定花朵只能放在未被目标占用的活跃空格。
- 目标描绘：在相邻格子上按住鼠标拖动；松开时匹配资源库形状，匹配成功后生成目标。可直接覆盖已有目标进行重画，资源库不存在该形状时取消并保留原目标。
- 删除与缩小棋盘：删除花块中的格子，或缩小棋盘切到花块时，会完整移除该花块及其预置花盆，避免留下残缺或空的目标记录；可撤销恢复。剩余空格可重新描绘花块，或使用“裁剪空格子”后保存。
- 棋盘整理：画布底部的“裁剪空格子”删除未被目标或预置内容使用的格子；“恢复全部格子”按当前棋盘宽高恢复完整网格。
- 栅栏编辑：选择“栅栏”后依次点击两个相邻的现有格子；重复操作会删除该栅栏。
- 关卡配置：在关卡 JSON 中编辑 `targets`、`given`、`fences`；`given.fixedFlowers` 是游戏中不可改变的固定花朵，`given.presetPots` 是玩家开局后继续补画的预置花盆。难度由关卡内容动态计算，不写入配置文件。
- 资源库：双击形状可编辑坐标数组；被关卡引用的资源不能删除或修改 ID。
- 花块颜色：六色颜色组保存在 `asset.json` 的 `colors` 分类中，并在资源库以只读色卡展示。
- 保存：右上角“保存”会先校验精确覆盖、形状、围栏和资源引用，再统一写入本地文件。

关卡中的 `targets[].shape` 是归一化目标形状，`solutionCells` 是标准解位置；全部标准解必须无重叠地精确覆盖 `activeCells`。
`targets` 不保存颜色；每次开始或重试关卡时会打乱六色花块颜色组，再按目标顺序循环分配颜色。

## 独立关卡列表

左侧“关卡集”可切换“花田”、“Shape Fill”和“花田试玩 · 前25关”。花田关卡存放在 `level/`，导入的 140 个 Shape Fill 关卡存放在 `shape-fill/`；新增、删除和下一关均在当前列表内操作，切换列表保留未保存修改。保存统一校验所有列表，只写入有改动的关卡；未编辑的主线文件保持原样。

Shape Fill 转换棋盘、目标形状、标准解、时限、静态围栏，并接入冰冻、砖块、机关门。原始 JSON 保留在 `shape-fill-source/`，不参与游戏加载或编辑保存。编辑器内部 ID 使用 `100000 + 原关卡编号` 避免与花田冲突，`sourceId` 保留原编号。

本地 WebView 扫描三个关卡目录；HTTP 浏览器预览通过 `level-catalog.json` 加载完整列表，保存时同步更新该索引。浏览器仍为只读预览，编辑保存使用 Windows 的 `start.exe` 或 macOS 的 `Start.command`。

导入脚本：`node tools/import-shape-fill.mjs <原始关卡目录>`。此命令会重新生成 Shape Fill 导入文件、原始备份及列表索引，重新导入前应备份已编辑的 Shape Fill 关卡。

## macOS 启动

在 Finder 中双击 `Start.command`，或在 FlowerPuzzle 目录运行 `./start.sh`。首次启动会创建本项目专用的 `.venv-macos/` 并安装依赖，需要网络连接。支持 Apple Silicon 和 Intel Mac，需预先安装 Python 3.11–3.13（例如 `brew install python@3.12`）；也可用环境变量 `FLOWER_EDITOR_PYTHON` 指定 Python 路径。

原生窗口支持关卡编辑、保存、刷新和三个关卡列表。文件保存至本项目目录，不依赖启动时的工作目录。关闭窗口即可退出。浏览器预览仍是只读模式。

## Shape Fill 三种机制

在“进入编辑 → 关卡 → Shape Fill 机制”中操作。所有坐标以棋盘左上角 `(0,0)` 为原点；标准解仍覆盖全部活跃格（包括砖块格）。新增、删除、调整机制支持撤销/重做，并随关卡保存。缩小棋盘或删除格子时，越界机制会同步清理。

- **砖块**：设置次数后，在画布上点击或拖动放置。未破碎的砖块阻止绘制；每个新有效花块对所有存活砖块贡献一次，花块失效或移除时返还。计数归零后永久破碎，本次试玩不再恢复。
- **冰冻**：设置秒数与触发次数，`0` 表示不限。新加入的格子触碰冰冻区域后，整个花块锁定，不能删除或续画；同时触碰多个区域取最长时间。倒计时结束解锁，有限次数用尽后冰冻格消失。
- **机关门**：点击“新增机关门”，依次选“端子 A / B”在画布定位，再选“绘制门边”点击相邻格的公共边。可为一扇门绘制多段边，最后点“应用机关门”。点击已有门可修改，或直接删除。有效花块接通端子时开门，失去连接后关门并清除跨门花块。

机关门默认使用“花块网络 · 可配对其他端子”，复用 Shape Fill 的端子独占配对规则，并优先保留已有连接。还可选择同一花块或仅自身端子模式。关闭的门、静态围栏和该门自己的门边阻止网络连通。

画布显示棕色数字砖块、蓝色冰冻及锁定倒计时、紫色关闭门边和绿色虚线开启门边。试玩重试时恢复全部机制初始状态。提示避开尚未破碎的砖块、关闭门边和锁定花块；它并不是带机关门的完整求解器。编辑保存验证配置合法性，不保证任意手工配置均可通关。

导入的 140 关已恢复原始机制配置：38 关有砖块、45 关有冰冻、20 关有机关门；不同机制可出现在同一关。运行测试：`node --test tests/*.test.js`。

Shape Fill 棋盘与花田采用相同的紧凑坐标：裁掉有效区域外围空白，宽高取有效区域包围盒，左上角归零。内部空洞和各格相对位置保持不变，目标标准解、预置、围栏、砖块、冰冻、机关门端子及门边统一平移。导入脚本自动执行此整理，原始数据仍保留在 `shape-fill-source/`。
